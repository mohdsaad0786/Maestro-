# Kubernetes deployment template

`maestro.yaml` is a template, not a complete hardened multi-tenant production release. Replace both image placeholders with pinned image digests. Provision an external PostgreSQL database with TLS, backups, and restricted network access. Create a `maestro` Secret with keys `api-token` (32+ random characters) and `database-url` (a PostgreSQL URL with required TLS settings). Supply per-provider read-only workload identity to the backend ServiceAccount through your cluster identity integration; override `automountServiceAccountToken` only when your identity integration requires it. Set `GOOGLE_CLOUD_PROJECT` and `AZURE_SUBSCRIPTION_ID` if scanning those providers. Install a TLS ingress with an identity-aware gateway in front of the dashboard; only expose `maestro-dashboard` publicly. Restrict network access to the backend and database. Configure Prometheus with a bearer credential to scrape `/metrics` on the backend service. There is deliberately one backend replica: scans are synchronous and coordination is per-process until a durable distributed scheduler is implemented.
